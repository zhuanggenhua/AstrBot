# 艾橙四层注入执行顺序（可执行版）

## 目标
把艾橙当前已确定的四层轻量注入方案，进一步收敛成一份真正可执行的拼装规则。

四层固定为：
1. `role-core`
2. `relevant-memory`
3. `session-event`
4. `reflection-hint`

本文件回答四个问题：
- 什么时候注入
- 各层取多少
- 顺序为什么这样排
- 命中为空时怎么降级

---

## 一、总顺序

最终拼装顺序：

```text
<role-core>
...
</role-core>

<relevant-memory>
...
</relevant-memory>

<session-event>
...
</session-event>

<reflection-hint>
...
</reflection-hint>
```

然后再接用户当前消息。

---

## 二、逐层规则

### 1. role-core（必带）
#### 来源
- `docs/aicheng_role_core_runtime.md`

#### 是否可省略
- **不可省略**

#### 目的
- 先锁死“艾橙是谁”
- 防止后续记忆 / 事件 / 纠偏喧宾夺主

#### 长度控制
- 固定短摘要
- 不允许把完整角色卡全文直接塞进去

---

### 2. relevant-memory（按需）
#### 来源
- Agent memory / `memory_recall`

#### 触发条件
满足任一时触发：
- 用户问稳定偏好 / 长期习惯 / 已确认决策
- 当前任务明显依赖过往长期事实
- 当前对话涉及老板已明确拍板过的稳定规则

#### 不触发条件
- 纯闲聊
- 当前轮次只是在修文案，不依赖历史事实
- 召回结果明显噪声过大

#### 条数上限
- 最多 3 条
- 默认优先 1~2 条

#### 命中为空时
- 整层直接跳过
- 不做占位文本

---

### 3. session-event（按话题）
#### 来源
当前阶段先从：
- `memory/YYYY-MM-DD.md`
- 项目进度文档
- 专项规范文档中抽取

后续如需要，再独立结构化。

#### 触发条件
满足任一时触发：
- 当前问题明显属于同一项目连续推进
- 当前轮次依赖本会话已经形成的决定
- 当前轮次涉及某 bug / 某决定 / 某阶段状态

#### 条数上限
- 最多 3 条
- 优先保留“还有效”的事件

#### 命中为空时
- 整层直接跳过

#### 典型内容
- 模型这轮先不动
- 艾橙重写完成后要主动告诉老板
- 当前决定不装 self_evolution，只参考其架构

---

### 4. reflection-hint（最轻）
#### 来源
当前阶段先从：
- `memory/YYYY-MM-DD.md`
- 项目文档中最近有效的纠偏项

#### 触发条件
满足任一时触发：
- 最近 1~3 轮内出现了明确纠偏
- 当前任务和最近一次风格偏差直接相关

#### 条数上限
- **最多 1 条**

#### 为什么只能 1 条
因为它最容易把 prompt 变成“纠错说明书”。
它只能是最后一层轻微扶正，不能变成主人格。

#### 命中为空时
- 直接跳过

---

## 三、降级策略

### Level 0：完整注入
适用：复杂任务、连续项目、明显依赖前文与长期规则

注入：
- role-core
- relevant-memory
- session-event
- reflection-hint

### Level 1：中等注入
适用：普通项目推进，但最近没有明显纠偏需求

注入：
- role-core
- relevant-memory 或 session-event（二选一或并存）
- 跳过 reflection-hint

### Level 2：最小注入
适用：普通短问答、轻闲聊、无需历史依赖

注入：
- role-core
- 其他全跳过

### Level 3：纯当前消息
理论上不建议。
只在系统已经天然持有足够角色上下文时考虑。
当前艾橙这条线默认仍保留 role-core。

---

## 四、实际判断流程

每轮开始前按以下顺序判断：

### Step 1
先带 `role-core`

### Step 2
问自己：当前消息是否依赖长期稳定事实？
- 是 → 加 `relevant-memory`
- 否 → 跳过

### Step 3
问自己：当前消息是否依赖本项目/本会话前置决定？
- 是 → 加 `session-event`
- 否 → 跳过

### Step 4
问自己：最近是否出现了仍然有效的明确纠偏？
- 是 → 加 1 条 `reflection-hint`
- 否 → 跳过

---

## 五、铁律
1. `role-core` 永远优先于其他层。
2. `reflection-hint` 只能最轻，且永远不能多条堆叠。
3. `session-event` 只保留当前仍有效的事件，不做历史堆积。
4. `relevant-memory` 只带强相关长期事实，不做模糊召回大杂烩。
5. 如果任一层内容质量不够，宁可跳过，不要硬塞。
