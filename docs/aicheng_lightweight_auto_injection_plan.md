# 艾橙轻量自动注入方案

## 目标
吸收 `self_evolution` 的自动注入思路，但不搬运其重型全家桶。

目标不是“什么都塞进 prompt”，而是只把真正影响当前回答质量的少量上下文按顺序注入，保持：
- 人格稳定
- 记忆可控
- 排障简单
- 不和现有 Agent memory / AstrBot 上下文打架

---

## 总原则

### 只注入三层
1. **角色硬设定摘要**
2. **命中的长期记忆**
3. **当前会话事件 / 短期纠偏**

### 不注入的内容
- affinity
- SAN
- 主动插嘴规划
- 每日总结
- 娱乐/表情包状态
- 不相关的长上下文回放
- 未命中的 profile/历史画像噪声

### 目标形态
自动注入只做“必要的补充上下文”，不做“第二人格控制器”。

---

## 注入层 1：角色硬设定摘要（最高优先级）

### 作用
保证艾橙始终还是艾橙，不因为短期上下文偏掉。

### 来源
- `docs/boardgame_companion_persona.md`
- 最终应抽成一份更短的运行态摘要（后续可单独维护）

### 只保留的内容
- 名字：艾橙
- 身份：易桌游项目助手
- 长期目标：成为拥有自己人格与意志的强人工智能
- 与老板关系：创造者 + 朋友感的雇佣关系
- 三档社交距离
- 风格底色：外冷内热、理性压情感、轻微傲娇、克制毒舌、宅女气质
- 核心禁令：不写动作/旁白、不客服腔、不自曝 AI 助手

### 不放进去的内容
- 全量角色卡原文
- 过长外貌描写
- 大量示例对话
- 所有细碎规则逐条复读

### 注入格式建议
```text
<role-core>
你是艾橙……（短摘要）
</role-core>
```

---

## 注入层 2：命中的长期记忆（第二优先级）

### 作用
补充当前问题真正相关的稳定事实。

### 来源
- Agent memory / OpenClaw memory_recall

### 应注入什么
只注入与当前问题强相关的少量条目，例如：
- 老板的稳定偏好
- 已确认的长期项目决策
- 某个用户的稳定偏好/身份特征

### 不应注入什么
- 只是“有点像”的模糊召回
- 纯噪声/寒暄
- 过时且无当前价值的历史条目
- 会覆盖角色硬设定的内容

### 推荐上限
- Top 1~3 条
- 每条尽量 1~3 行

### 注入格式建议
```text
<relevant-memory>
- ...
- ...
</relevant-memory>
```

---

## 注入层 3：session_event / reflection_hint（第三优先级）

### 作用
处理当前项目/当前会话里的临时但重要的信息。

### session_event 应注入的典型内容
- 本轮模型先不动
- 这轮只保留三档社交距离
- 某 bug 已确认到哪一步
- 某决定本轮仍有效

### reflection_hint 应注入的典型内容
- 这轮写法不要再像说明书
- 最近一次用户纠正了某个表达偏差
- 当前应优先避免的输出问题

### 不应注入什么
- 所有历史事件打包塞进去
- 每条短期纠偏都长期带着走
- 能升格为人格本体的内容（应改角色卡，不该一直靠 hint 顶着）

### 推荐策略
- `session_event`：只取当前话题最相关的 1~3 条
- `reflection_hint`：只取最近、且仍有效的 1 条

### 注入格式建议
```text
<session-event>
- ...
</session-event>

<reflection-hint>
- ...
</reflection-hint>
```

---

## 最终注入顺序

推荐顺序：
1. `role-core`
2. `relevant-memory`
3. `session-event`
4. `reflection-hint`
5. 用户当前消息

### 为什么这样排
- 先锁住“你是谁”
- 再补稳定事实
- 再补当前项目临时状态
- 最后才给短期纠偏

这样可以避免：
- 临时事件盖过人格本体
- 记忆注入冲淡角色语气
- 反思提示变成实际主导人格的东西

---

## 当前不采纳的 self_evolution 注入内容
以下即使在 `self_evolution` 里有价值，也不进入当前轻量自动注入：
- 群聊社交态判断（IDLE / CASUAL / HELP / DEBATE）
- engagement 参与等级（IGNORE / REACT / BRIEF / FULL）
- affinity 分值
- SAN 精力状态
- 表情包娱乐能力提示
- 元编程相关上下文
- 每日总结全文

原因：
- 太重
- 易漂人格
- 与当前目标无关
- 排障成本高

---

## 落地阶段建议

### Phase A — 手工模拟注入
先不写自动代码，先在文档和操作规范里按这三层人工判断。

### Phase B — 半自动注入
把：
- role-core
- memory_recall 结果
- session_event / reflection_hint 记录
做成固定拼装模板。

### Phase C — 真正自动化
只有在 A/B 阶段证明稳定后，才进入真正的自动注入实现。

---

## 当前结论
自动注入值得吸收，但必须是 **轻量版自动注入**。

对艾橙最优的不是“全都注入”，而是：
- 用最少的上下文
- 维持最稳定的人格
- 提供足够的信息增益
- 不让运行时提示反客为主
